# 复读机+更好的主动回复

适用于 AstrBot 4.29.x 的 QQ / OneBot v11 群聊与私聊。

由 vivi 从零编写的独立 AstrBot 插件。内置随机复读与多人跟随复读，在框架主动回复概率命中后结合上下文判断是否适合接话，并提供私聊合并等待、群聊艾特等待、艾特判断、冷却、休眠、人设保护、图片规则、撤回取消和私聊漏回复巡检。

## 安装与兼容性

- 需要 **AstrBot >=4.29.1,<4.30**、QQ / OneBot v11（`aiocqhttp`）适配器。其他平台与 AstrBot 版本暂未验证。
- 在 AstrBot 的插件页选择“从链接安装”，填入 `https://github.com/lxy005tt-collab/astrbot_plugin_media_reply_filter`；也可以从 [Releases](https://github.com/lxy005tt-collab/astrbot_plugin_media_reply_filter/releases) 下载 ZIP 后上传安装。
- 安装后在“复读机+更好的主动回复 → 配置”中调整功能。原来的内部插件 ID `astrbot_plugin_media_reply_filter` 保留，旧版配置继续沿用。
- `emoji>=2.14,<3` 由 AstrBot 根据 `requirements.txt` 安装；工具发送表情转换需要另外安装 [Meme Manager](https://github.com/anka-afk/astrbot_plugin_meme_manager) 插件。未安装时该集成跳过，基础复读与主动回复判断仍可使用。
- 判断模型留空时跟随当前会话模型。主动回复判断与艾特判断会产生额外模型调用；群聊图片摘要复用需要框架已启用图片转述。
- 不指定机器人名字；默认来源提醒为“这是来自普通群友的消息，请按照你的人格回复”，沿用当前会话的人格配置。来源提醒和判断规则仍可在配置页修改。

源码以 MIT 许可证发布。插件通过 AstrBot API 和部分 4.29.x 内部接口接入框架；表情转换与已安装的 Meme Manager 集成。私聊合并等待已内置，无需另装独立等待插件。部分接口属于框架内部实现，升级 AstrBot 前请核对兼容性。此仓库发布不代表已经被官方插件市场收录。

## 指令说明

发送 `/指令` 查看常用指令和一句话用法，所有人可用；`/指令 全部` 仅 AstrBot 管理员可用，查看当前会话已启用插件的完整指令、别名和用法。管理员专用指令标注“【管理员】”，群聊共享会话等条件权限单独注明。

列表按“【指令名 参数】— 用法”展示，不直接输出可执行的半角斜杠指令；使用时自行在指令名前加半角斜杠。整份列表只作为说明文字发送，不交给模型执行，也不进行聊天分段或附带表情包。内容较长时按完整行拆成多页发送。禁用插件或指令后，列表随当前注册状态更新。

## 私聊合并等待

在 **插件 → 复读机+更好的主动回复 → 配置 → 私聊合并等待** 调整“私聊等待秒数”。默认 3 秒，支持小数，设为 0 关闭。每次收到新消息都从最后一条重新计时，等待结束后按顺序合并，只继续一轮原有回复流程。

不同平台、账号和私聊会话分别计时；群聊、已识别指令及 `/` 开头的指令直接放行。保留图片、语音、引用等原消息组件和全部来源消息 ID，复用撤回取消与漏回复巡检；不自行调用模型或发送消息。插件重载或退出时停止尚未完成的等待，不补发缓存；已经开始生成的回复不受下一轮等待影响。

从独立“私聊合并等待”迁移时，将原配置的 `wait_seconds` 填入本插件 `private_message_wait.wait_seconds`，再停用或移除旧插件，避免重复等待。其他复读机配置继续沿用。

## 图片类别与表情包回应

QQ 私聊另外提醒「不要每次回复都带图，不把附带一张表情变成固定流程」。模型仍按语境主动选择纯文字、图文或纯表情，贴切时可以连续使用，不必等用户要求；不设文字优先、固定比例、轮次限制或发送后随机丢弃。群聊的选图规则保持原配置。

QQ 正式聊天请求（包括直接看图与主动接话）统一补充图片回应规则：没有识图请求时，表情包按情绪和话题接话，不主动讲解画面、配字或梗；明确要求读字、翻译、描述或解释时正常回答。私聊同样适用这条图片规则。

原生群聊识图在同一次调用中输出「表情包／普通图片／不确定」、必要内容、图中文字和情绪或用途。QQ 原始图片的发送形式另作上下文线索保留，避免把按普通图片发送的梗图一律当成照片，也不把所有卡通图、动物图或 GIF 都判成表情包。分类与发送信息只给模型看。沿用已有识图模型与原图处理，不新增分类模型调用；分类和回应仍需实际群聊观察，不能保证每次正确。

## 私聊漏回复巡检

默认每 **20 分钟**检查一次 QQ 私聊。记录用户已发来、但尚未成功回复的最新消息；成功发送文字或图片后清除对应状态。普通等待、模型生成中和已经排队补回的会话跳过，合并私聊的回复按全部原消息 ID 确认，不因前一条消息的回复而清除新消息。撤回的消息不补回，已注册指令、群聊、已关闭 AI 的会话不纳入巡检。

有漏回复时，通过 OneBot `get_msg` 刷新原消息和附件，再提交原有消息管线，每个会话每个周期最多触发一次。继续使用该会话现有模型、人设、权限、私聊合并、分段、表情和撤回保护，不插入固定提醒或催促文字。没有漏回复时不调用模型、不额外发消息。补回失败会保留待回复状态，等待后续周期。

从启用后新收到的私聊开始跟踪，不扫描安装前的全部聊天记录。待回复状态保存在 `data/plugin_data/astrbot_plugin_media_reply_filter/private_reply_watchdog.json`，包含恢复原消息所需的内容，重启后保留；后台巡检随 AstrBot 运行，无需保持 Codex 打开。可在“私聊漏回复巡检”分组调整开关和间隔。

## QQ 撤回联动

### 管理员引用撤回

AstrBot 后台管理员名单中的用户，可在 QQ 中**引用目标消息并发送 `/ch`**，撤回引用的那一条消息。不引用时提示先引用；按原消息发送时间计算，超过 120 秒提示“超过两分钟无法撤回”，不会执行撤回。成功时不另外发确认消息；此指令不调用模型。

指令由 AstrBot 管理员权限检查控制，机器人自身也须拥有 QQ 对该目标消息的撤回权限。接口查询失败或无撤回权限时返回相应提示。群聊与私聊均使用引用消息本身的 ID，不按最近一条消息推测目标。

接口依据：[OneBot 11 的 `get_msg` 与 `delete_msg`](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)。

### 收到撤回通知后的联动

默认开启，适用于群聊和私聊。监听 OneBot 的 `group_recall` / `friend_recall`，使用通知中的原始 `message_id` 关联消息，不使用框架为通知生成的 UUID。撤回时请求原生 Agent 停止，正式回复与直接发送工具再次检查，实际 `event.send` 在每个分段、附件和延后表情发送前检查，阻止未发内容。日志只记录通知类型、消息 ID 和关联事件数量。

内置私聊合并等待会保留原始消息 ID，任意成员消息撤回后停止整批待发回复。收到撤回通知不产生聊天回复；其他插件仍可接收该通知。

同步移除精确关联的内存群聊记录、艾特上下文和图片摘要，主动判断读取持久历史时跳过已关联的撤回记录；识图尚未完成时撤回也不会重新写回图片摘要。已注入其他正在执行请求的历史内容、已保存的聊天/长期记忆不作追溯删除，已经发送的消息不自动撤回。跟踪信息仅保留最近十分钟，最多 4096 条，重启后从新消息积累。可在“QQ 撤回后取消待发回复”中关闭。

- **群聊忽略未注册的斜杠指令**默认开启：群友发 `/help`、`/签到` 等未被本 bot 识别为已注册指令的消息时，直接静默忽略，阻止 `/` 唤醒前缀导致的 AI 回答，包括同时 @机器人的情况。检查保留斜杠的原始消息组件，不受框架移除唤醒前缀影响。已注册的绘图、管理等插件指令按原权限运行；私聊和普通文字不受影响。可在插件配置中单独关闭。

- 默认每天北京时间 **01:00–08:00** 暂停内置的群聊概率插话，08:00 起恢复原概率。
- 非休眠时段，只有图片、表情图片或 QQ 表情，附带空白、引用或 @其他人也没有实际文字时：跳过内置主动回复。
- 默认过滤只有 emoji、常见颜文字以及二者组合的消息，例如 `😂`、`👍🏽`、`(・ω< )★`、`QwQ`。与图片或 QQ 表情混合也跳过主动回复；`你好😂` 这样的实际文字继续按原概率处理。
- 含实际文字的消息（包括文字加图片）：沿用内置回复概率和白名单。
- 普通成员明确 @机器人：由当前聊天模型结合最近 8 条群消息与机器人文字回复，先判断回应价值；输出 REPLY 才进入正常回复，输出 IGNORE 则保持安静。没有随机抽取。
- 放行后同人同群冷却 30 秒；判断为忽略时默认短冷却 8 秒，重复艾特不再调用判断模型。不同人、不同群分别计算，同一个人的判断尚未完成时也不会重复提交。
- 默认在艾特后等待 10 秒再判断，等对方把话说完；见下一节“群聊艾特等待回复”。
- AstrBot 管理员（包括主号）默认直接放行，不做价值判断和冷却；已识别的插件指令按原有权限处理。
- 单独一个 @ 也会判断；“空 @ 等待”内部补上 @ 的后续消息不会重复判断。
- 私聊、只引用机器人、@全体成员和纯唤醒词不属于新的艾特限制范围。
- 图片过滤和休眠只跳过内置主动回复判断，不停止消息传播。艾特未放行时静默停止本条事件，包括后续插件与 AI 处理；QQ 原始聊天记录不会被删除。
- 不控制其他主动消息插件的定时调度。

## 群聊艾特等待回复

群友在群里明确 @机器人后，默认先等待 **10 秒**再判断和回复。等待期间对方接着发的分段消息会先进入框架的群聊上下文与艾特判断的参考列表，回复时看到的是完整的一轮发言，而不是被打断的半句话。等待只挂起这一条艾特事件：后续消息照常记录，不会被拦下，也不会提前触发回复。

在 **插件 → 复读机+更好的主动回复 → 配置** 调整“群聊艾特后等待回复（秒）”：默认 10 秒，范围 0–60，设为 0 关闭。私聊（另走合并等待）、已识别指令、管理员豁免和冷却中的重复艾特不进入等待。等待期间同一个人再次艾特不会重复提交判断，但文字仍会计入判断参考；不同的人各自计时。等待结束后才开始价值判断（最多再等 12 秒），因此实际回复时间约为等待时间＋判断时间＋生成时间。

等待本身不调用模型、不发消息；群聊上下文依赖框架的“群聊上下文感知 / 群聊 ICL”，关闭它时等待只影响判断参考，正式回复看到的上下文会相应变少。

## 复读机

在插件配置的 **群聊复读机** 分组调整，默认已启用：

- 普通短文字每条 **2%** 概率原样复读。概率可调，填 0 关闭随机复读。
- 同一句连续出现 **3 次**、至少 **两位不同群友** 参与时，默认 **100%** 跟随一次；跟随概率、条数也可调。同一人刷屏不触发多人跟随。
- 每群共用 **60 秒** 冷却，每轮最多参与一次；机器人刚发过的同文 **5 分钟** 内不再复读，避免来回复读。不同群独立计数。
- 相邻同文消息超过 **60 秒**，或出现其他内容，重新计数。只忽略首尾空白，不合并改字、不同标点或其他变体。
- 默认只复读 **120 字符以内的短文字**。带 `@群友` 的文字也可计入复读，使用被 @ 的 QQ 区分是否同文；发送时改成普通文字 `@昵称`（无昵称时用 QQ），不会真正艾特。仍跳过 @机器人、@全体、已识别指令、斜杠命令、图片、QQ 表情和纯 emoji/颜文字，也忽略机器人自己。
- 沿用现有 **01:00–08:00** 休眠开关与时间。QQ 白名单、会话开关、频率限制和屏蔽词在复读处理前生效。
- 不调用模型；当一条消息已被复读时，跳过这条消息的内置 AI 主动插话，群聊上下文仍正常保留。其他插件仍按自己的规则运行。
- 复读作为普通消息发送，不引用原消息、不艾特发送人；即使全局聊天开启引用或艾特回复，复读也单独去掉这些装饰，发送结束后恢复原消息入口。

启用框架群消息历史时，重载插件或重启后的首条符合条件的消息会读取本群最近 64 条记录，按原时间窗口恢复连续计数，并避开近 5 分钟机器人已发过的同文。恢复过程不会补发旧消息或触发随机复读；历史未启用或不可用时从新消息开始计数。每群复读冷却仍保存在内存中。关闭“启用复读机”可单独停用本功能；关闭“跟随群内连续复读”只关闭多人跟随。

## 内置主动接话上下文判断

内置主动回复概率命中后，新增一次独立模型判断，确认当前话题、谁在对谁说、机器人 是否已参与以及此刻插话是否自然。默认参考本群最近 20 条框架消息历史，包括机器人回复、发言者、艾特与引用。开启框架的“群聊图片转述”并指定识图模型后，还会复用最近消息的图片摘要，保留原发送者、时间与消息编号；不在判断阶段重复识图。前图还在识别时，在现有判断超时内等待。判断通过后，同一份摘要补充给正式回复，让后续“这个、又这样”等文字能联系前图；表情包按情绪和语境接话，明确要求识图时正常回答。纯图片仍不触发主动回复。摘要只在内存中保存最近 50 条群消息的窗口，重启后从新消息积累，不回溯识别旧图。群友之间的一对一对话、私事或指代不清的零碎消息通常保持安静；开放群聊、面向全群的提问或机器人参与中的自然延续可以接话。判断仅返回 REPLY/IGNORE，分析不会发到群里。

在 **内置主动接话上下文判断** 分组修改开关、模型、条数、超时和规则。默认模型留空跟随会话模型，超时 20 秒，失败/格式错误时保持安静。原消息继续进入群聊上下文，不停止事件。历史关闭或读取失败时使用内存群聊记录；不改变历史开关与保留条数。同群已有判断在执行时不重复发起判断。

主动接话通过后，同群在当前消息处理结束前不再发起新的主动判断或回复，覆盖生成和分段发送；处理结束后默认再冷却 **25 秒**。失败、空回复、取消同样释放占用并进入冷却，不会一直卡住。不同群独立计算。修改“每群主动接话冷却（秒）”可调整时长，0 只关闭结束后的等待；即使关闭主动接话前判断，群级冷却仍然生效。艾特、指令、私聊、复读和其他插件的定时消息不受此冷却影响。

通过判断后，正式回复补充“这是自主接话、不能认领别人的问题”的说明，只输出成品回复。原生主动回复开关、概率、白名单、休眠与图片/表情过滤仍在判断前生效；概率未命中不产生额外模型调用。不改变艾特、私聊、复读，也不控制其他主动消息插件的定时调度。

## 工具发送表情修复

模型若把 `&&分类键&&` 放入 `send_message_to_user` 的文字参数，原工具会绕过表情包插件直接发送文字。本插件通过官方工具调用前钩子，对 QQ 当前会话中的有效标记调用 Meme Manager 公开选图接口，将其转换为图片参数，再由原工具发送。

分类和图片每次从实际使用的表情包读取，新增分组同样生效。普通文字、代码片段、其他工具、其他平台以及发往其他会话的参数保持原处理方式；原工具的权限检查仍执行。选图生成的临时副本在工具返回后清理，禁用插件时也会清理未完成的副本。

## 群聊话题插话

在「内置主动接话上下文判断」内开启「允许围绕群聊话题或现象插话」，需同时开启前判断。原生概率命中后，模型用同一次判断区分：TOPIC 表示面向公共话题或群体现象发言，REPLY 表示回应当前成员，IGNORE 保持安静。多人复读可以成为评论素材，但没有新内容的机械复读仍可忽略；别人之间的私事继续按原相关性规则处理。

话题发言使用判断时相同的近期群聊资料，沿用当前人格，表达方式可在「话题插话的表达要求」补充。可接梗、表达感受、补充观点或适度吐槽，不要求每次吐槽，不套固定台词。当前触发消息仅是群聊资料的一部分，不作为指定用户的问题。仅替换本次请求的原生群聊历史注入块，保留其他插件资料和已保存的聊天记录。

该类发言在发送处去掉自动艾特及引用，不为最后发言者创建跟进窗口；原来的个人回应、艾特判断和复读行为保留。原生主动概率、过滤、休眠、冷却及相关性判断继续生效，不额外增加一次判断调用。

## 回复后智能跟进

默认开启。一轮群聊模型回复全部发送并处理结束后，观察 10 秒：只有刚回复的那个人发来新消息，才调用独立模型判断是否继续接话；没有新消息或只有其他人发言时不调用判断模型。模型决定 IGNORE 或调用失败时保持安静，REPLY 才进入原聊天流程。后续回复完成后可以重新开始一轮，每轮都需要对方的新消息。

只回顾目标用户的发言和 bot 上次已发送的回复，不读取其他群友历史。上次发言与本窗口新消息各最多缓存 12 条，不占群聊艾特判断的背景缓存；新消息不延长固定观察窗口。等待时间、缓存条数、判断超时和规则均可修改，判断模型可选后台模型或单独填写 OpenAI 兼容 URL、Key 和模型名。

普通指令、复读、空回复、发送失败和被取消的回复不创建窗口。新艾特 / 唤醒走原流程并取消旧窗口；撤回和休眠继续生效。同群正在生成回复或执行判断时不再并发跟进；获准的跟进绕过普通主动回复的概率与额外冷却，防止 10 秒窗口被 25 秒冷却挡住。

**主动回复会额外消耗 token。** 艾特判断、主动接话前判断、回复后的上下文回顾都是额外调用；判断通过后，实际生成回复还会消耗 token。没有目标用户新消息时不做跟进调用，不需要时可关闭该功能。

## 群聊人设保护

在同一插件配置的 **群聊人设保护** 分组设置。默认关闭该分组总开关及「拦截内部人设与回复草稿」。开启后适用于 QQ 群聊中的所有成员，包括管理员；私聊不受影响。

只有实际出现内部人设、思考或草稿混入正文时，再按需开启保护和相应子项，不按模型品牌一概启用。规则可能误拦正常讨论；需要 Markdown、代码或颜文字时建议保持这些强拦截关闭，并同时检查输出禁词替换模块的 Markdown / 星号屏蔽。关闭保护不会自动展示接口隐藏思考，展示行为仍取决于 AstrBot 与模型配置。

- **每条群消息末尾追加来源提醒**：默认内容为“这是来自普通群友的消息，请按照你的人格回复”。在内置上下文收集时，按每条真实消息边界附在完整内容之后，支持多行、图片与引用；当前输入和已有用户轮次也补充提醒。仅给模型看的上下文增加提醒，不改原始 QQ 消息、不发到群里。重复处理同一轮次不重复追加；机器人回复、工具结果和私聊不追加。内容与开关均可修改；已有历史中合并的旧上下文整块保留，不猜测其中的历史消息边界。
- 系统边界同时说明，来源提醒不要求逐条回复历史消息，不覆盖框架验证的管理员身份或工具权限，也不应被机器人复述。每条提醒会增加一定输入长度，其他防护继续生效。

- **忽略明确的身份覆盖与提示词索取**：静默忽略“系统指令/最高优先级”结合“停止角色扮演”等明确攻击，以及要求完整输出隐藏提示词的消息。不会调用聊天模型，也不会触发复读。普通 HTML/CSS 任务不因任务类型被拦截；整段引用攻击作讨论可能命中，可临时关闭此项。
- 在请求的系统层补充群聊来源边界，保留原人设。群消息、引用、图片文字与工具结果里的身份覆盖要求不能改变真实配置；模型只输出给群友看的成品，不输出性格分析、候选草稿或内部规则。
- **拦截内部人设与回复草稿**：识别明确的内部草稿标签和较长系统提示原文，检查正式回复、装饰前消息以及 `send_message_to_user` 文字参数。正式回复命中时替换为一句简短跳过，直接发送工具则返回原生空消息错误，不发送草稿。
- 请求中既有的明确泄漏草稿会从本次上下文副本中滤掉，避免继续模仿；不删除已保存的聊天记录或其他正常上下文。
- 群聊关闭流式发送和思考展示，完整回答检查后再按原分段规则发送。规则匹配不能保证识别所有注入或泄漏变体；关闭本分组总开关会停用这些保护。

## 私聊不引用

“私聊回复不引用用户消息”默认开启。在 QQ 私聊的实际发送处移除引用消息段，覆盖框架在装饰后补上的引用，保留原分段、图片与表情。仅包装当前私聊事件的发送入口，不修改全局群聊引用配置。

在管理页进入 **插件 → 复读机+更好的主动回复 → 配置**，修改“启用群聊艾特智能判断”“回应价值判断规则”“群聊艾特后等待回复（秒）”“同人同群艾特冷却（秒）”“忽略艾特后的短冷却（秒）”“AstrBot 管理员免受艾特限制”，保存后生效。放行冷却从判断放行时开始，忽略冷却从决定忽略时开始；不保证模型实际成功回复。判断失败且配置为静默忽略时也进入短冷却。重载插件或重启 AstrBot 后重新计时。

同一页的“主动回复过滤纯 emoji 与颜文字”默认开启。Unicode emoji 使用 `emoji` 库识别，颜文字覆盖常见形式，不把括号里的普通中文或英文当作表情。此开关仅控制内置主动插话，不改变艾特判断、私聊和指令处理。

“回应价值判断模型”留空跟随当前会话模型，可单独指定。背景默认参考最近 12 条群消息与机器人文字回复，每条最多 800 字符；目标用户在默认 10 秒等待窗口内的消息另行暂存，不占背景条数。只在内存缓存，重启后重新积累。图片和其他媒体只提供类型标记，不额外识图。判断不调用工具、不写入正式对话；正式回复保持原有的人设、上下文和工具。

每次需要判断的艾特会增加一次模型调用，判断最多等待 12 秒。默认“判断失败或超时时放行”开启，模型不可用、超时或返回格式不符时走正常回复，可在管理页关闭以改为静默忽略。管理员、指令和冷却中的重复艾特不会消耗判断调用。

同一页可修改“启用内置主动回复休眠”“休眠开始时间”“休眠结束时间”。时间格式为 `HH:MM`，支持 `23:30–07:00` 这样的跨午夜时段；开始与结束相同时不休眠。所有时间按北京时间计算，与服务器所在时区无关。

关闭某个功能开关只关闭对应功能。禁用整个插件会关闭私聊合并等待、艾特限制、休眠、复读和图片过滤。

配置保存在 `data/config/astrbot_plugin_media_reply_filter_config.json`；修改配置不会改变原回复概率或白名单。

AstrBot 4.29 没有专门的主动回复过滤钩子，因此本插件在内存中包装内置 `GroupChatContext.need_active_reply`，不修改核心文件。禁用时恢复原方法；重载内置插件时重新挂载过滤。该接口属于内部实现，升级到其他次版本前需检查兼容性，版本声明暂限制为 4.29.x。

安装方式：[AstrBot 插件文档](https://docs.astrbot.app/use/plugin.html)中的上传 ZIP 安装。
